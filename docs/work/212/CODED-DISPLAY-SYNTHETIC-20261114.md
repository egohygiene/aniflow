Checkpoint 1 admits one bounded source profile: progressive H.264 with a uniform, chroma-aligned right/bottom crop from macroblock-aligned coded pixels to the declared display. It does not infer crop offsets or resize. Nonzero left/top crop and other cropped codecs remain refused.

The complete default display probe and an uncropped native probe must agree on every frame's stream, rational clock, keyframe, pixel/color/aspect and side data. Every observed uncropped rectangle must exactly produce the declared display. Both coded and displayed pixels retain `maximum_pixels`; this is post-probe admission before extraction, not a decoder memory sandbox. FFprobe stream discovery may decode. Initial `-show_streams` reported coded height 90 while the complete decoder-initialized observation reported 96; only the latter is the final coded-dimension witness, and its remaining stream facts must match the initial inventory. The failed strict preliminary comparison is retained.

Extraction keeps decoder cropping disabled and explicitly selects `crop=w=160:h=90:x=0:y=0:exact=1` before the existing bitexact RGB conversion. Fresh extraction and sparse-reference observations recheck the geometry. The old uncropped v1 report shape remains unchanged; only the selected cropped profile carries `source_geometry`.
