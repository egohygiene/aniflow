# Plain root help — November 14, 2026

Relates to [Flow #22](https://github.com/egohygiene/flow/issues/22).

Actual POSIX PTY checks found that the existing wordmark selector correctly
chose the plain fallback, while Clap still added ANSI styling on narrow/unknown
terminal and empty `NO_COLOR` paths. Literal root `--help` and `-h` now write
Clap's color-unaware semantic `Display` text when decoration is unselected.
Wide supported interactive help keeps its existing static wordmark and optional
SGR styling. No domain, logging, normal parsing or sibling dependency changes.

The [selected-CLI observation](PTY-20261114.json) records **27 cases / 34 actual
CLI invocations**, with binary SHA-256 `4856af6d7af68195fc3206779d8e845322bc7cbeadc92e2e8a0fd3db840fa6b0`.
The executable was built using Rust 1.85.0, locked/offline dependencies and two
jobs at source tree `211c201ef8664a4cb490114a7c61e981b59cd9a0`; this documentation/receipt is a later-only delta.
Both root-help spellings preserve semantic bytes after removing the exact single
static mark and, only on color-capable paths, ordinary SGR styles. Redirected,
narrow, unknown/missing/dumb terminals, missing/invalid widths, empty `NO_COLOR`
and `CLICOLOR=0` root help are plain, without ANSI. Version, subcommand help,
errors, semantic `help`, structured release description and unsupported
completion/man help requests contain no wordmark and preserve native exits/text.
The native structured result remains valid JSON. Presentation creates no files
in the fresh working directory outside the checkout; inputs remain byte-identical.

The shared observer lives in Flow `tools/check_root_help_pty.py`; its eight
adversarial boundary cases reject missing/repeated art, semantic changes, extra
stderr, changed exits, color on plain paths and cursor controls. This owner
retains its own independently built CLI. Root-help assets were not redesigned;
human design approval, assistive-technology review, other native platforms and
release qualification remain separate. Completion/man generators are absent,
so only their unsupported help requests were observed. No media/model/provider,
hosted CI, release or publication occurred.
