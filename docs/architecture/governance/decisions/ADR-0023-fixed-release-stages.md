# ADR-0023 — Fixed selectable release stages

Proposed for #107. Source publication or merge does not ratify this record.

Existing recipes already own native children, manual lyrics, caption/final-file
reviews, local posting packages and retention. A second workflow executor or
acceptance ledger would duplicate those authorities. Instead expose one fixed
ordered release journey starting at current accepted source assembly. Closed
automated/manual-artifact/automated-with-review/disabled intent selects existing
typed requests. Current owner evidence alone advances a stage. Disabled optional
stages require reasons; unknown capabilities/modes are unavailable. No fallback
or arbitrary dependency/command language is introduced.

Reobserve exact source/predecessor file, clock, configuration and native/review
evidence before returning a bounded handoff. A changed subject/configuration
cannot retain a prior decision through this view. Manual delivery delegates
import and supplied review to existing owners; no auto-approval or new review
database. Cross-holon scheduling and human-task UX remain in Flow. Future
identity, provenance, creator mark, credentials, signature, timestamp and
post-upload hooks are visible but cannot satisfy dependencies before a concrete
owner binding is implemented. Existing separate capability implementations are
not implicitly adopted or declared absent by a composition stub.

This first view does not provide arbitrary manual-video adoption, order changes,
model selection, media processing or posting. It preserves originals and exact
native rational clocks. Descriptive metadata, visible overlays, invisible marks
and signed credentials remain distinct. Qualification and broader composition
stay with feature #107 and Flow #88 last; both source contracts and regression
cases are authored/uncompiled/unrun. No release, human decision or publication
authority is inferred.

## Proposed source-entry extension — November 10, 2026

A separate versioned source/indexed entry view reuses the current recipe/status
and prepared-frame review owners before a master exists. It records no duplicate
workflow state or guessed final identity. Explicit supplied exact decisions use
the existing review writer without starting assembly. Only current accepted
final-video bytes can bind the unchanged optional release tail. Entry context
pins source/configuration, reached native phase/manifest and review identities.
An unresolved carrier, rejected review or missing parent binding never counts
as completed media. Existing accepted-master v1 keeps its meaning. Native/visual/
platform/workflow qualification remains deferred; this ADR stays proposed.
