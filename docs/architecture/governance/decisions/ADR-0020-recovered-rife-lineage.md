# ADR-0020 — Recovered RIFE lineage

Proposed for #110/#107. Source inclusion is not ratification or native safety.

A complete recovered spatial carrier is current accepted evidence with mixed
historical/current origin. It is not a native Upscayl collector output. Add an
explicit recovered-input wrapper over the existing serial RIFE renderer and
native v3 lifecycle instead of coercing its lineage into the old spatial input.
The immutable original inspection/clock stays original, while actual recovered
PNG hashes and geometry identify the pixels submitted to RIFE. Keep distinct
raw carrier pins and processing fingerprints. Historical tool/model execution
stays unknown; new RIFE observations establish no creative approval.

The original and native-spatial v1 wire meanings stay unchanged. A v2 RIFE
assembly carrier carries recovered evidence; native assembly has a separate v3
operation for that index. Existing source/held-frame mapping, exact full-duration
2x clock, native checkpoints, private pinned components, direct pair argv,
finite capture/admission limits and final assembly validation retain ownership.
The native IO/render lifecycle is shared with the existing spatial adapter;
there is no second model algorithm, graph engine or acceptance database.

Only the existing bounded CFR/SDR/CPU-or-explicit-device profile is admitted,
with at most 50000 source/100000 derived frames and its current cut/hold rules.
No silent processing order, resampling, implicit model acquisition or resource
safety promise is added. Readback rechecks actual current native/parent owners.
Broader media, cut correctness, native performance, perceptual quality, resource
and release qualification remains deferred to flow #88, scheduled last.

The subsequent fixed recipe extension uses a separate v2 recovered request,
intent, plan and status. It nests the existing spatial request and an optional
explicit enabled RIFE configuration. Omitted interpolation observes no RIFE
components. Native child plans await actual accepted predecessors; the parent
locates existing sparse/RIFE/assembly acceptance and owns no second database.
Existing v1 roots are not adopted as v2. Final handoff projects actual assembly.
