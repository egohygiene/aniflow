# Review prepared recipe frames from the CLI

Select `review_prepared_frames: true` when creating an indexed or source-entry
recipe. The normal recipe pauses before assembly after accepted preparation,
upscale and any selected RIFE interpolation/carrier. The review subject is that
exact final frame set, ordered hashes, index, source and configuration.

```bash
aniflow --output json video frame-review status \
  --run-directory "/absolute/paused recipe"
```

The private `aniflow.prepared-frame-review/v1` names the actual image directory,
index, complete count, directory/index digests, manual context and current
decision state. Inspect the images yourself. `review.context_sha256` and
`review.subject_sha256` are the exact fingerprints for your declaration.
Status reuses ordinary native acceptance and source/index/tool/model/intent
checks; it creates no review directory, repairs no partial child and launches no
media provider. Disabled or not-yet-accepted subjects are explicit errors; use
`video music-video-status` to inspect earlier phases.

Supply your own `aniflow.manual-review/v1` JSON with `schema`, `context_sha256`,
`subject_sha256`, explicit `decision` (`approve` or `reject`), `reviewer` and
`notes`. No field or decision is generated by the CLI.

```bash
aniflow --output json video frame-review record \
  --run-directory "/absolute/paused recipe" \
  --declaration operator-frame-decision.json
```

The declaration is closed JSON of at most 64 KiB, with existing stricter field
bounds. Recording rechecks its fingerprints, holds parent and existing fixed
child writers, and uses the no-overwrite manual checkpoint. Already initialized
assembly, repeated decisions, stale context and unaccepted predecessors refuse.
Rejection stays retained; edits/new settings need their own workflow. A later
observation failure may leave a retained declaration; inspect status before retry.

Resume assembly separately with the original `video music-video` arguments and
`--resume-run-directory`. Approval is an operator declaration about exact bytes,
not authenticated identity, native/visual qualification or publication authority.
No video, audio, lyric review or original image is changed. If an interpolation
carrier is absent, normal recipe resume owns binding it; status never adopts it.

The SDK is `music_video_recipe::prepared_review::{status,record}`. Both recipe
entries and lyrics attachment share the immutable request resolver. Existing
recipe status wire shapes are unchanged. Envelopes use
`video_frame_review_status` and `video_frame_review_record`. Keep complete
reports private; human output escapes locators before printing.
