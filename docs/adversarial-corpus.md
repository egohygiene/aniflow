# Adversarial temporal-media corpus

The #24 corpus combines deterministic media recipes with the repository's
existing temporal, audio, provider, pipeline, validation and cache suites.
This pass is **authored, unqualified work**. Tests, build, formatting, lint,
schema validation, native media execution and hosted qualification remain
unrun under #64. No real media was used or changed.

## Author, inspect and generate

The source of truth is `scripts/corpus/recipes.py`, the native profile list,
and the owning existing test/fixture sources. The reviewable projection is
[`conformance/temporal-v1/catalog.json`](../conformance/temporal-v1/catalog.json).
Each case includes a stable ID, validity class, media type, seed/parameters,
intentional corruption description where applicable, expected outcome and
typed diagnostic names, and exact file/path/digest inventory. Empty frame
directories are represented explicitly. Separate coverage records link
existing tests and historical audio IDs without reclassifying their evidence.

```bash
# Explicit authoring after reviewing a recipe or referenced-source change:
task corpus:catalog

# Read-only drift detection; never rewrites canonical files:
task corpus:check

# Existing parent; output leaf must be absent and outside the checkout:
task corpus:generate OUTPUT="/tmp/aniflow-corpus-inputs"
python3 -B scripts/temporal-corpus.py verify --directory "/tmp/aniflow-corpus-inputs"
```

Generation invokes no media tool, provider, test or model. It uses Python 3.10+
standard library only. Generated bytes are synthetic; writing the catalog or
materializing a bundle is not a test result. There is no implicit download.
Source files and artifacts are bounded to 2 MiB individually, the generated
bundle to 32 MiB and 4,096 inventory nodes. Generation rejects existing output
directories, links, traversal and source-checkout destinations. It stages
bytes, exclusively claims a new output directory and publishes the ownership
marker last. An interruption may leave an incomplete directory; verification
refuses it. Choose a fresh destination after inspecting an interrupted run.
The tool never recursively cleans or adopts an arbitrary output directory.

## Explicit qualification

Later, when #64 qualification is authorized, provision dependencies separately:
Rust/Cargo with locked dependencies already cached, Python 3.10+, and the
`jsonschema` package. Native tiers additionally require FFmpeg/FFprobe with
libx264. These commands never install or download those dependencies.

```bash
task corpus:qualify OUTPUT="/tmp/aniflow-corpus-pr"
task corpus:native OUTPUT="/tmp/aniflow-corpus-native" \
  FFMPEG="/usr/bin/ffmpeg" FFPROBE="/usr/bin/ffprobe"
task corpus:native TIER="extended" OUTPUT="/tmp/aniflow-corpus-extended" \
  FFMPEG="/usr/bin/ffmpeg" FFPROBE="/usr/bin/ffprobe"
```

| Tier | Execution | Time budget | Evidence/output budget |
| --- | --- | --- | --- |
| PR | Catalog/schema/generator checks; focused public-contract/runtime/recovery/validation/cache suites | 15 minutes | 64 MiB |
| Scheduled | PR tier, public native temporal tests, synthetic PNG/PCM/Y4M decode checks and repeated container encodings | 30 minutes | 128 MiB |
| Extended | Scheduled tier plus all Rust targets and published-contract checks | 60 minutes | 256 MiB |

An isolated Cargo build has a separate 4 GiB budget in all tiers. Commands use
direct argument arrays, offline Cargo and fresh generated inputs. Capture is
bounded to 4 MiB per process. Native calls have 10–20 second bounds and a 32 MiB
maximum individual FFmpeg allocation. Unix process groups are terminated on
timeout/limit errors; other platforms refuse this runner rather than reporting
skipped Unix suites as qualified. Pure recipe generation remains portable.
Polling budgets are safeguards, not filesystem quotas or a security sandbox.

The runner retains `receipt.json`, process arguments, exit states, log digests,
runtime identity and exact tool identity. Native checks assert stream metadata,
frame/sample counts and decoded pixels/PCM where defined. Same-toolchain
encoding runs twice and must produce identical bytes. Expected malformed
decoder refusals are distinct from crashes, timeout and missing dependencies.
Source bundles and source bindings are rechecked after execution. A missing
dependency, skipped platform boundary, timeout or assertion failure never
produces a passing qualification receipt. The run output is retained for review.

The existing CI workflow gains the read-only drift gate. The additional corpus
workflow supports explicit manual tier selection. Weekly execution is gated by
repository variable `ANIFLOW_CORPUS_QUALIFICATION=enabled`; this implementation
does not enable it or dispatch any workflow. The workflow separately provisions
dependencies before the offline qualification step and retains failure logs.
All actions in the new workflow are pinned by commit.

## Coverage and limits

| Family | Authored coverage | Boundary / remaining qualification |
| --- | --- | --- |
| Images | Tiny RGB/RGBA, color metadata, extreme aspect ratios, misleading extension, truncation, bad signature and header-only zero/huge dimensions | Native decoding/pixel equality unrun; full image-format/orientation breadth remains a corpus expansion |
| Frame sequences | Empty/single/multiple, gaps, nonzero start, mixed dimensions, duplicate content and ambiguous/lexical names | These are inventory recipes, not proof that every shape is accepted by a provider; exact timeline/drop/reorder assertions remain in temporal tests |
| Timing and stream selection | Existing 30 protocol recipes plus absent-stream and audio-only cases; fractional CFR, VFR refusal, signed offsets, reordered PTS/DTS, cover art, extra streams, explicit selection/discard and A/V mismatch | Protocol evidence is distinct from native container evidence; unsupported VFR/offset processing remains visibly refused |
| Containers | Deterministic raw Y4M; MP4/MOV/Matroska encoding profiles for CFR, B-frames, SAR, duplicate video and audio/video streams | Exact executable/version pinned per run; encoder/codec/platform breadth and damaged indexes need later fixtures, not inferred support |
| Audio | Integer silence, square tone, terminal impulse, clipping, discontinuity, mono/stereo/six-channel, 8/16/24-bit, single-sample and malformed headers | Existing 148 audio index IDs remain preserved; no real-model or perceptual quality claims |
| Timed text | Unicode/RTL/CJK/emoji, BOM/CRLF, SRT/LRC/WebVTT/TTML/plain, empty/reversed/overlapping/out-of-order cues, invalid UTF-8/NUL, unsupported markup and bounded byte limits | Public decode/JSON round-trip and typed refusal authored; loss-authority assertions remain in existing timed-text tests |
| Runtime and adapters | Exact source locators for unavailable/version mismatch, nonzero exit, timeout/cancellation/descendants, capture/artifact limits, invalid/missing output, links and explicit effects | Existing hermetic provider profiles stay in their owning conformance kit; installed AI tools/models are not required or qualified |
| Recovery and acceptance | Interrupted runs, changed inputs/locks/reports, invalidated dependency frontiers, exit-zero rejection, current acceptance and read-only status | Existing assertions are preserved; the earlier alignment cancellation failure remains #64 |
| Cache | Hits/misses, expiry, corruption, origin proof/current validation, isolated output bytes, rerun interruption, invalidation/pruning, storage refusal and contention; complete multi-artifact reuse and sibling rejection | #34/#69 coverage is authored and unrun; crash recovery and platform limits remain explicit |

Finite fixture coverage does not establish support for every file. This is the
bounded implementation checkpoint requested before #10 release conventions.
The broader #24 corpus parent and original acceptance criteria remain open;
the table records expansion areas, and #64 owns the accumulated execution and
audit. #69 authors execution of exact nonempty output sets for `One`,
`OneOrMore` and `Many` ports, with per-artifact acceptance, full-set resume and
cache checks. `Optional`, unbound ports and empty output sets remain refused.
Those tests are also authored and unrun under #64. The corpus does not close
platform gaps or qualify a release.

## Promoting a fuzz regression

1. Minimize the reproducer using synthetic, redistributable bytes. Keep secrets,
   personal data, malware and uncontrolled resource payloads out of the corpus.
2. Assign a stable `ani.corpus.*` ID and name the relevant public boundary.
3. Add a deterministic recipe with explicit bounds, seed, parameters and the
   precise intentional corruption. Preserve a source issue and license note.
4. Add an assertion for the typed diagnostic or exact accepted artifacts,
   digests, cleanup and immutable source. Exit success alone is insufficient.
5. Regenerate the catalog explicitly, review the source/digest diff, and collect
   a separate qualification receipt at an exact commit/environment when allowed.
6. Extend a tier only within its budget; larger workloads require a reviewed,
   opt-in profile. Never silently regenerate expected results in CI or weaken
   an assertion to hide a regression.

Decision impact: no new product architecture boundary or ADR is required. This
repository-owned test corpus exercises the existing temporal, provider,
acceptance and cache contracts; their proposed ADRs retain their prior status.

## Native audio contribution from #80

Checkpoints #93–#95 author classic PCM24/float32 inspection and native signal
coverage in `tests/audio_inspection.rs`, `tests/audio_signal.rs`, the in-module
WAV/signal tests and the companion Python schema cases. Cases include signed
packed 24-bit values, asymmetric stereo, exact tail/duration, finite floating
headroom, subnormals, malformed headers, nonfinite refusal, source mutation and
resume. Historical PCM16 report and configuration behavior remains separately
covered. Source locators and digests are authored metadata, not test results.
No generator, drift check, native tool, model or test was executed; #64 retains
qualification and #24 retains broader corpus ownership.
