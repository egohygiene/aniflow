# aniflow v0.2.0 Processing Graph

## 1. Purpose

Upgrade the initial vertical slice into a real, resumable music-video pipeline
that can remove supported Gemini visible watermarks, upscale frames with the
Upscayl NCNN backend, and preserve extension points for the complete envisioned
media workflow.

## 2. Scope

### Included

- Ordered per-frame processor chains.
- Typed Upscayl NCNN adapter.
- Typed Gemini Watermark Remover CLI adapter.
- Generic frame, audio, and whole-video command processors.
- Frame integrity and dimension continuity checks.
- Prepared subtitle burn or mux.
- Optional Renderflow handoff stub.
- Versioned delivery manifest.
- Pipeline-aware dependency diagnostics.
- Compact per-frame Gemini removal decision metadata.
- Per-stage resume behavior plus per-frame resume for generic processors.

### Deferred

- Rust-native Gemini watermark-removal algorithm.
- Arbitrary DAG scheduling.
- Model download and installation management.
- Visual flicker and optical-flow continuity analysis.
- Variable-frame-rate reconstruction.
- Cross-run content-addressed cache.
- Final Renderflow API and derivative artifact implementation.

## 3. Architecture decisions

### AD-001 — Ordered chains before arbitrary DAGs

Frame, audio, and whole-video transformations execute as ordered chains.
Current processors consume one complete upstream artifact set and produce one
complete downstream set, so a DAG scheduler would add complexity without
unlocking a required v0.2.0 use case.

### AD-002 — Typed high-value adapters

Upscayl and Gemini Watermark Remover receive typed configuration and generated
arguments. Generic processors retain a placeholder-based escape hatch.

### AD-003 — CLI boundary before Rust migration

The existing `gwr` CLI is the first implementation. The pipeline kind remains
stable when the algorithm later moves into a Rust-native provider.

### AD-004 — Renderflow remains downstream

Aniflow produces a temporal master. Renderflow remains an optional consumer for
formats, thumbnails, previews, transcripts, posters, metadata, and derivatives.

## 4. Functional flow

1. Inspect source streams and timing.
2. Extract PNG frames and lossless PCM audio.
3. Run each enabled frame processor into a new stage directory, using native
   directory mode where supported.
4. Validate sequence, file integrity, and uniform dimensions.
5. Assemble the processed frame set.
6. Run optional audio processors and restore the chosen audio.
7. Apply prepared captions, subtitles, or lyrics.
8. Run optional whole-video processors.
9. Publish the master.
10. Optionally hand the master to Renderflow.
11. Publish the delivery manifest and checksums.

## 5. Acceptance criteria

- [ ] Pipeline schema version 2 accepts multiple ordered frame processors.
- [ ] `gemini_watermark_remover` generates the supported `gwr remove` command.
- [ ] `upscayl_ncnn` generates a valid `upscayl-bin` command.
- [ ] A failed processor preserves earlier stage outputs.
- [ ] Resume skips complete stages and valid generic per-frame outputs.
- [ ] Final frame count and ordering match the source extraction.
- [ ] Dimension discontinuities fail before assembly.
- [ ] Optional audio and video processors use direct, shell-free execution.
- [ ] Renderflow is disabled by default and does not block normal runs.
- [ ] Every successful run produces `output/master.mp4`.
- [ ] Every successful run produces `delivery/manifest.json`.
- [ ] `doctor --pipeline` reports all enabled external dependencies.
- [ ] CI validates formatting, Clippy, tests, and the synthetic media path.

## 6. Validation commands

```bash
cargo fmt --all -- --check

cargo test --all-targets
./scripts/smoke-test.sh
```

## 7. First-run strategy

1. Run `passthrough.yml` to establish timing and audio parity.
2. Run a short representative clip through
   `gemini-clean-upscale.example.yml`.
3. Review watermark regions, fine linework, motion continuity, dimensions, and
   A/V synchronization.
4. Adjust model, scale, tile size, GPU selection, and native worker arguments.
5. Process the full music video only after the short clip passes.
