# aniflow v0.1.0 Vertical Slice

## 1. Objective

Process one real `.play()` music video from source media to a release-ready MP4
through an inspectable and resumable pipeline.

## 2. Constraints

- Optimize for time-to-first-success.
- Preserve the source unchanged.
- Use FFmpeg and FFprobe instead of reimplementing media operations.
- Use one Rust crate until module boundaries are proven.
- Support arbitrary external per-frame programs.
- Treat constant-frame-rate video as the supported v0.1.0 input class.
- Do not duplicate `renderflow` derivative-generation responsibilities.

## 3. Required flow

```text
source video
  → inspect
  → extract PNG frames and PCM audio
  → optionally transform every frame
  → validate frame set
  → assemble encoded video
  → restore audio
  → optionally burn or mux subtitles
  → publish master MP4 and manifest
```

## 4. Functional requirements

### FR-1: Source inspection

The engine must use FFprobe to record duration, dimensions, average frame rate,
estimated frame count, codecs, audio presence, and subtitle presence.

### FR-2: Isolated run

Every new run must create a timestamped workspace and place generated artifacts
only beneath it.

### FR-3: Frame extraction

The engine must extract frames as `frame-%08d.png` and preserve ordering.

### FR-4: Audio extraction

When audio is present, the engine must extract the first stream to a lossless
PCM intermediate.

### FR-5: External processing

The engine must invoke a configured executable directly for each frame, expand
documented path placeholders, enforce bounded concurrency, and require the
expected output file.

### FR-6: Validation

The engine must reject an empty, missing, differently counted, or differently
named output frame set before assembly.

### FR-7: Reconstruction

The engine must assemble frames at the inspected average frame rate and encode
using explicit pipeline output settings.

### FR-8: Audio restoration

The engine must map the rebuilt video and extracted audio into the master
timeline and limit output to the shorter stream.

### FR-9: Subtitles

The engine must accept a prepared ASS or SRT file and support `burn` and `mux`
modes.

### FR-10: Resume

The engine must preserve stage markers, preserve completed frame outputs, and
refuse to resume if the source checksum changed.

### FR-11: Observability

The engine must report live stage state and preserve external command logs,
source metadata, manifest state, and checksums.

## 5. Acceptance criteria

- [ ] `aniflow doctor` identifies FFmpeg and FFprobe availability.
- [ ] `aniflow inspect <video>` prints correct core media metadata.
- [ ] `aniflow plan` shows the exact v0.1.0 stage sequence.
- [ ] A synthetic two-second video succeeds through the passthrough pipeline.
- [ ] The final output contains video and restored audio.
- [ ] A configured external processor receives every source frame.
- [ ] Missing or failed processed frames prevent assembly.
- [ ] Re-running `resume` skips completed stages and frames.
- [ ] Changing the source prevents resume.
- [ ] ASS subtitles can be burned into the result.
- [ ] SRT or ASS subtitles can be muxed into MP4 as `mov_text`.
- [ ] The final output and source have SHA-256 provenance in the manifest.
- [ ] Paths containing spaces are passed without shell splitting.
- [ ] CI runs formatting, linting, unit tests, and the synthetic media test.

## 6. Deferred work

- Variable-frame-rate timeline preservation
- Multiple audio and subtitle tracks
- Stage fingerprints and cross-run cache
- Per-frame retry limits and timeout enforcement
- Dimension and continuity analysis across every frame
- Duration-delta and A/V sync validation thresholds
- Whole-video processor registry
- Rust-native, Python, container, ComfyUI, and remote providers
- `renderflow` delivery-manifest handoff

## 7. First real-video validation

Use the unmodified video first with `pipelines/passthrough.yml`. Confirm
duration, audio sync, orientation, and output playback. Then duplicate
`pipelines/anime-upscale.example.yml`, select the desired model and scale, and
run a short source excerpt before committing GPU time to the complete video.
